# 카톡 레이더 — M1 실기기 수집 검증

Redmi Note 14 5G / Android 15에서 카카오톡 알림 수집 가능성을 검증하는 프로젝트다. 서버·AI 요약·본폰 발송은 아직 연결하지 않았다. 앱에는 인터넷 권한이 없다.

> **현재 상태 (2026-09-16):** 실제 KakaoTalk callback은 앱에 도달하지만 M1 v0.1.0의 `MessagingStyle`-only parser가 관찰 callback을 모두 unsupported로 분류했다. 다음 작업은 backend가 아니라 parser 진단·fallback·room identity 수정이다. [실기기 디버그 노트](docs/DEBUG_NOTES.md) 참고.

## 구현한 기능

- 알림 접근 설정과 연결 상태 확인, 대상 방 발견·선택, 수집 시작·중지.
- 카카오톡 그룹 MessagingStyle 알림 파싱. 다른 앱·개인 대화·그룹 요약 알림은 원문 저장 대상에서 제외.
- Room DB에 원문·발신자 가명·시각·URL 저장. 방 제목과 알림 식별자를 함께 확인.
- 이전 메시지 창의 HMAC 서명을 영속 저장해 알림 갱신 중복을 억제. 동일 문장의 반복 횟수와 서로 다른 시각을 보존.
- 마지막 수집, 저장 건수, 재노출 억제, 불확실한 메시지 창, 미지원/요약 알림 진단.
- 시스템 파일 선택기를 통한 원문 포함 JSONL 내보내기, 수집 중지·로컬 삭제.
- 7일 보관 정리. 앱 시작·화면 갱신·알림 처리 시 수행하며 앱이 강제 종료된 동안 정시 삭제를 보장하지 않는다.

## 설치와 첫 실행

1. 제공된 `kakao-radar-m1-debug.apk`를 서브폰으로 옮겨 설치한다. 개인 테스트용 debug 서명 APK다.
2. 앱에서 **알림 접근 설정 열기**를 눌러 ‘카톡 레이더’의 접근을 허용한다.
3. 대상 카톡방의 알림을 켜고 새 메시지를 기다린다. 소리·진동은 별도로 꺼도 되지만 실제 수집 여부는 확인해야 한다.
4. 앱의 **발견한 방에서 선택**에서 대상 방을 확인하고 **수집 시작**을 누른다.
5. 새 메시지를 몇 개 받은 뒤 저장 건수와 최근 원문을 확인한다. 첫 알림 창에는 카톡이 함께 제공한 이전 메시지가 포함될 수 있다.
6. [실기기 검증 안내](docs/DEVICE_TEST.md)를 따라 화면 꺼짐·재부팅·폭주 구간을 비교한다.

직접 설치한 APK의 알림 접근 메뉴가 제한되는 경우에는 Android가 표시하는 앱 정보의 제한 설정 안내를 확인한다. 기기의 보안 검사를 일괄 해제하거나 보호 기능을 우회하지 않는다. 접근 권한은 사용자가 단말에서 직접 부여해야 한다.

## 현재 한계

카카오톡이 이 기기에서 어떤 알림 형식을 제공하는지 아직 실측하지 않았다. 그룹 MessagingStyle 없이 일반 텍스트 알림만 제공하면 방이 발견되지 않는다. 이 경우 ‘미지원/요약 알림’ 진단이 늘며 원문은 저장되지 않는다. 이 숫자에는 요약용 알림도 포함되므로 메시지 누락 수로 해석하지 않는다.

알림에 없는 메시지와 사진·파일 본문을 복원할 수 없다. 알림 창이 겹치지 않거나 시각이 없으면 ‘순서 확인 필요’로 표시한다. 동일 내용·발신자·시각·개수의 완전히 동일한 창은 재노출과 새로운 반복을 구별할 수 없다. 이런 플랫폼 정보의 한계까지 100% 수집으로 표현하지 않는다.

방 제목만 같아도 다른 알림 키이면 자동으로 따라가지 않는다. 안정적인 shortcut ID가 없는 경우 재부팅·카톡 업데이트 뒤 방을 다시 선택해야 할 수 있다. 대상 방을 바꾸기 전 기록도 내보내기에 포함되므로 비교 시 room_id로 구분한다.

발신자는 설치별 HMAC 가명으로 저장하지만 대화 원문은 평문으로 앱 전용 저장소에 남는다. Android 백업을 비활성화했으며 별도 DB 암호화는 구현하지 않았다. 내보낸 파일에는 원문이 포함되고, 사용자가 선택한 저장 위치가 클라우드이면 동기화될 수 있다.

## 소스에서 빌드

필요 환경: JDK 17, Android SDK Platform 35 및 Build Tools, Gradle 8.9. 실제 사용 버전은 빌드 설정에 고정되어 있다.

`android` 폴더에서 `gradlew.bat testDebugUnitTest assembleDebug lintDebug`를 실행한다. macOS/Linux는 `./gradlew`를 사용한다. Android Studio에서는 `android` 폴더를 열고 SDK 위치를 지정한다. APK 경로는 `app/build/outputs/apk/debug/app-debug.apk`다.

자동 검사에는 순수 메시지 창 비교 테스트와 Robolectric Android 15 파서·Room 트랜잭션 복구 테스트가 포함된다. 실제 단말 테스트는 USB 디버깅 연결 후 `gradlew.bat connectedDebugAndroidTest`로 실행할 수 있다. 이 명령은 테스트용 DB만 생성·삭제한다.
