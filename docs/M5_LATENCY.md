# M5 — 지연·긴급 후보·열람 측정

서버 0.6.0에서 구현했다. 사용자 운영 선택은 정기 요약 23:00, urgent 꺼짐이다. 긴급 후보를 켜려면 별도 정책 변경이 필요하다.

urgent는 중요도 기본 90 이상, 최근 15분에 분석한 관심 후보만 대상으로 한다. 기본 300초 cooldown, 기존 대기 큐 우선, 정기 시간표 유지, 공통 조용한 시간·일일 알림 상한·중복 fingerprint·방 허용 목록·최신 profile 검사를 적용한다. 중요도 점수는 모델 판단이며 사실 검증/긴급성 보장이 아니다.

`GET /v1/latency`는 기기 Bearer 인증으로 최근 7일의 수집→서버 업로드, 업로드→분석 p50/p95, 발송 큐→Telegram API 수락 및 큐→상세 페이지 첫 열람 p95를 집계한다. 음수 지연은 단말 시계 차이 샘플로 분리한다. 초기 적체 업로드도 포함되므로 최초 설정 때의 높은 p95를 steady-state 성능으로 해석하지 않는다.

`POST /v1/digests/{delivery_id}/opened`는 해당 digest HMAC 인증과 유효 기간/방·기기·원문 상태를 확인한 뒤 첫 열람 시각만 기록한다. 상세 페이지가 정상 데이터를 표시한 후 호출한다. 이 시각은 브라우저 열람을 의미하며 폰 알림 표시 시각이 아니다. `handset_notification_display_measured:false`는 실제 단말 ack가 없다는 뜻이다.

검증은 threshold 미달/오래된 후보 제외, urgent 기본 비활성, cooldown, 정기 슬롯 보존, 수동 검증·urgent의 공통 quota, 서명 없는 열람 차단과 첫 열람 멱등성이다. 전체 회귀에는 기존 조용한 시간·동시 실행·삭제·중복·응답 소실 시험도 포함한다. 실환경의 5분 목표, 급변하는 방의 수집률, 본폰 표시 latency는 아직 통과로 기록하지 않는다.
