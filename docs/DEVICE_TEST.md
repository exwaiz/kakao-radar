# Redmi Note 14 5G 실기기 검증

대상 환경: 사용자 제공 Redmi Note 14 5G / Android 15. 2026-09-16 APK 설치 후 실제 사용에서 KakaoTalk callback은 관찰됐지만 현재 parser가 모두 unsupported로 분류했다. **따라서 수집률 장기 측정 전에 parser-format 진단 APK를 먼저 검증해야 한다.** 상세 결과는 [DEBUG_NOTES.md](DEBUG_NOTES.md)에 기록한다.

## 다음 parser 진단 APK: 첫 10~50개 메시지

1. 앱을 설치하고 알림 접근을 허용한다.
2. 카톡 대상 방 알림을 켜고, 카톡 화면을 닫은 상태에서 새 메시지를 받는다.
3. 먼저 **callback / parsed / unsupported-by-reason** 카운터가 어떻게 움직이는지 본다.
4. privacy-safe structure diagnostic에서 MessagingStyle, EXTRA_MESSAGES, TITLE/TEXT/SUB_TEXT/SUMMARY_TEXT 존재 여부를 확인한다.
5. 같은 방 연속 알림에서 shortcutId/tag/key가 안정적인지 확인한다.
6. parser가 실제 방을 안정적으로 인식한 뒤에만 수집 시작·dedup·장기 수집률 검증으로 넘어간다.

진단 로그에는 extras key name과 존재/count 같은 구조 정보만 남기며 다른 방의 원문·닉네임을 복제하지 않는다. 현재 단계에서 unsupported가 계속 늘면 HyperOS 절전보다 parser failure histogram을 먼저 본다.

## 2~3일 기록표

각 구간마다 시작·종료 시각, 전체 빌드 번호·카톡 버전, 배터리 잔량, 충전 여부, 네트워크, 카톡·수집 앱의 배터리/자동 시작 설정을 기록한다.

| 구간 | 조건 | 확인 |
|---|---|---|
| A | 화면 켜짐, 카톡 백그라운드 | 본문·발신자·URL과 메시지 수 대조 |
| B | 카톡 대상 방을 열어 둠 | 알림이 발생하지 않아 빠지는 메시지 여부 |
| C | 밤새 화면 꺼짐 6~8시간 | 누락 집중 구간, 연결 상태, 배터리 변화 |
| D | 짧은 시간에 메시지가 몰림 | 알림 갱신 중복·정상 반복·창이 끊기는 구간 |
| E | 절전·자동 시작 설정 비교 | 기본값 대비 수집과 배터리 차이 |
| F | 재부팅 후 잠금 해제 전·후 | 저장 데이터 유지, 자동 재연결 여부와 지연 |
| G | 최근 앱 목록에서 제거 | 수집 지속 또는 중단·복구 시점 |
| H | 설정에서 강제 종료 후 재실행 | 재실행 후 복구; 중단 중 수집은 기대하지 않음 |

실제 네트워크 업로드는 이 버전에 없으므로 서버 오프라인 복구·전송 중복 검증은 M2에서 수행한다. 첫 버전은 재시작 뒤 로컬 메시지 창을 복원해 알림 재노출을 처리한다.

## 결과 대조

앱에서 **원문 포함 JSONL 내보내기**를 선택한다. 대조할 실제 메시지를 확보한 시간 구간으로 표본을 제한한다. 읽지 않은 메시지 배지와 콜백 수는 분모로 쓰지 않는다.

`tools/compare_capture.py`는 내보낸 파일과 별도 대조 JSONL을 비교한다. 대조 파일 한 줄은 `{"text":"실제 메시지", "source_time":1789550000000}` 형식이며 시각은 UTC Unix 밀리초다. 시각이 없는 표본은 text만 넣을 수 있지만 시간 검증이 생략된다. 원문 문자열은 그대로 유지한다. 대조 파일은 사용자가 직접 확인한 메시지를 담아야 하며 수집 결과로 자동 생성하면 수집률 검증이 아니다.

실행 예: `python tools/compare_capture.py capture.jsonl ground-truth.jsonl --room-id ROOM_ID --from-ms START --to-ms END`

두 파일 모두 동일 방·동일 구간을 사용한다. 도구는 텍스트가 같고, 대조·수집 양쪽에 원본 시각이 있으면 5초 이내인 항목을 일대일로 대응시킨다. 정상 반복 문장을 개수만큼 따로 매칭한다. 일치율은 표본 수집률이며 전체 기간으로 일반화하지 않는다. 수집 파일에 남은 미대응 항목은 시간·표본 경계 오류일 수도 있으므로 확정 중복으로 부르지 않는다.

초기 목표는 500건 이상 표본의 텍스트 수집률 95% 이상, 확인된 중복률 1% 이하, URL 보존율 99% 이상이다. URL·정상 반복·방 구분은 별도 수동 대조한다. 실제 원문을 확보하지 못하면 전체 수집률은 ‘미검증’으로 남긴다.

## 다음 단계로 넘어갈 조건

기본·야간·폭주 구간 결과가 목표를 충족하면 M2 서버 저장·동기화를 진행한다. 누락이 크거나 방이 발견되지 않으면 이 기기와 카톡 버전의 알림 형식을 먼저 검토한다. 이 앱의 자동 테스트 통과는 카카오톡 실기기 수집률 통과를 뜻하지 않는다.
